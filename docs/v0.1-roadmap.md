# Scary Gary v0.1 implementation roadmap

This roadmap orders the contracts resolved by Wayfinder issues [#2](https://github.com/scwlkr/scary-gary/issues/2) through [#11](https://github.com/scwlkr/scary-gary/issues/11) into the shortest dependency-safe route to a rough-complete v0.1. The feature and evidence identifiers refer to the binding [v0.1 acceptance contract](./v0.1-acceptance.md).

## Delivery rule

Build one runnable vertical increment at a time:

```text
M0 Foundation -> M1 Canonical sprites -> M2 Routine Gary
  -> M3 Desktop illusions -> M4 Gary Event -> M5 Lifecycle
  -> M6 Distribution candidate -> M7 v0.1 release
```

- Each milestone lands on `main` with its focused automated and Windows evidence before the next milestone closes.
- Use the production WPF process, assets, adapters, and self-contained `gary.exe` from the first visible slice. Throwaway parallel implementations do not count.
- Add policy through the I/O-free `GaryBrain`, serialize effects through `GaryController`, render through the shared presentation layer, and keep Windows access behind the narrow adapters resolved in #10. Add only the boundary needed by the current slice.
- Every visible slice includes stop, Esc, unsafe-environment, topology-change, and failure cleanup appropriate to what it can display. Safety is never postponed to a cleanup phase.
- Focused milestone checks may exercise part of an A01-A09 gate, but partial evidence never passes a complete acceptance row or hands-on run. M7 reruns every required gate against the final artifact.
- Cosmetic debt may carry only when the acceptance contract explicitly permits it. No Primary Scene, Safe Fallback, timing, cleanup, lifecycle, platform, trust, or removal requirement moves beyond v0.1.

## M0 — Repository foundation and first honest pixel

**Outcome:** A pinned .NET 10 WPF repository builds and tests one unpackaged, self-contained `win-x64` process. A manually composed `GaryController` can drive the pure `GaryBrain` from Starting to a static canonical loiter and Stopping, while one bounded `OverlayWindow` displays Gary without focus or input capture.

**Build:**

- Add the solution, one production project, one test project, pinned `global.json`, locked dependencies, deterministic clock/entropy seams, and Windows CI.
- Establish the `Domain`, `Application`, `Presentation`, `Platform.Windows`, and `Infrastructure` boundaries without separate assemblies or a dependency-injection framework.
- Implement monitor selection, physical-pixel/DIP conversion, a bounded transparent click-through/no-activate overlay, audio/overlay cleanup, and the smallest deterministic developer rehearsal seam used by later hands-on checks.
- Publish one self-contained `gary.exe`; do not add Startup, persistence, runtime networking, elevation, an updater, a helper process, or a service.

**Closure evidence:**

- Locked restore, build, unit tests, and single-file publish pass on the milestone commit.
- Tests prove deterministic Starting/Stopping decisions, serialized effect ordering, signed negative-coordinate and 100/150/200% geometry conversions, and cleanup after a failed overlay start.
- A clean supported Windows 11 x64 run without a system .NET runtime records one correctly scaled canonical still, click/drag/scroll pass-through, unchanged foreground focus, clean process exit, and no elevation or network prompt.
- The dependency/API inventory contains no Desktop-content access, global hook, display-setting mutation, system-volume control, admin API, or runtime network path. This starts A02, A05, A08, and A09 evidence without claiming those full gates.

## M1 — Canonical sprite and sound pipeline

**Depends on:** M0's renderer, manifest reader, package validation, and rehearsal seam.

**Outcome:** The approved #7 production bible becomes redistributable, shippable input: all routine frames, props, signs, Foley, and standalone Gary Event assets build into the real executable. The rough behavior contact sheets remain references only and never ship.

**Build:**

- Redraw/export the complete approved clip inventory as per-frame 4x RGBA sources, retaining canonical Gary's hand-painted pixel-edged identity and 205-logical-pixel target.
- Build the three atlas pages and `gary-atlas.v1.json` with rectangles, pivots, sockets, frame timing, links, and mirror permission. Keep the Event face and sound standalone and never mirror signs or the Event face.
- Add all twelve exact sign faces, the generic mystery-file prop, garbage prop, complete Foley inventory, and the single mastered Event sound.
- Record creator, source, and redistribution provenance for every image, sound, font, tool output, and dependency.

**Closure evidence:**

- Automated asset validation proves every approved clip/frame budget, atlas field, pivot/socket, mirror rule, exact sign, transparent-RGB/padding/extrusion rule, PNG alpha, WAV format/level rule, and required embedded asset. Black, white, and magenta matte checks expose no fringe or checkerboard.
- Contact sheets and a runnable atlas viewer show every clip at 100%, 150%, and 200% scale, including maximum-extremity crops and prop attachment.
- Owner visual review confirms the everyday identity against `scarygary.png`, the Event identity against `scarygary-jumpscare.png`, sign legibility, fake-icon genericity, and the accepted sound balance. Evidence is attached to the milestone commit.
- This completes the asset-production portion of A08; packaging remains open until M6 and is rerun in M7.

## M2 — Routine Gary

**Depends on:** M1's production atlas, sounds, and catalog contract.

**Outcome:** A Portable Run delivers safe loiter plus taskbar walk, Gary Doze, sprint, fall, and all twelve signs through the real scheduler. Gary feels varied rather than noisy and already leaves no pixels, props, or audio behind when interrupted.

**Build:**

- Complete Starting, Awake, Garynap, and Stopping behavior needed by this slice, including the 30-90-second start, 10-45-second quiet gap, 70/20/9 eligible-action weights, recency relaxation, cooldown classes, environment stability, and signal priorities available so far.
- Implement F00, F01, F03, F06, F07, and F13 with their production entrance, performance, exit, local Foley chance, Primary Scene, and Safe Fallback.
- Keep action clocks monotonic and frame-rate independent. Esc begins the session-local three-hour Garynap now; M5 later adds the complete cross-launch control lifecycle.

**Closure evidence:**

- Fake-clock and seeded-entropy tests prove this slice's mode transitions, priority, weights, recency, cooldown, durations, sign inventory, action completion, immediate stop/Esc/unsafe cleanup, and prop/audio ownership.
- Focused catalog tests prove F00, F01, F03, F06, F07, and F13 are wired to their required assets and fallbacks. These contribute to A01-A03 and A08.
- A supported Windows 11 one-file run records each Primary Scene and fallback at 100% scale, passive input/focus, routine audio and muted audio, taskbar/edge fallback, process stop, Esc/Garynap hide, and neutral return.
- F00, F01, F03, F06, F07, and F13 have linked results; any carried defects fit only their allowed-polish cells.

## M3 — Desktop illusions and cursor reactions

**Depends on:** M2's scheduler, animator, cleanup, and production assets.

**Outcome:** Every remaining routine action works through supported observations or a harmless visual simulation: Start-button sit, edge peek, behind-window crawl, cursor stare/follow/flee, garbage drag, and fake icon theft.

**Build:**

- Complete F02, F04, F05, and F08-F12 without inspecting Explorer child windows, reading Desktop items, changing foreign windows, or installing global hooks.
- Add the narrow cursor, taskbar/work-area, monitor/DPI/topology, eligible-window, virtual-desktop, and safety probes. Missing or ambiguous facts become `Unavailable` and activate only the specified fallback or ineligibility.
- Keep every action monitor-local. Requery invalid geometry, clean up within the declared bound, wait two stable seconds, and never fight z-order.

**Closure evidence:**

- Parameterized timing/invalidation, pure geometry, controlled-window adapter, and safety-boundary tests cover this slice of A01, A03, A05, A06, and A09.
- F02, F04, F05, and F08-F12 each have linked Primary Scene, coherent exit, interruption cleanup, and Safe Fallback results.
- Windows evidence covers E03-E11: mixed 100/150% displays with negative coordinates, 200% scale, available taskbar edges/auto-hide, Explorer restart, ordinary and invalid window targets, input/focus pass-through, cursor thresholds and monitor crossing, virtual desktops, lock/UAC/exclusive full screen, topology changes, and higher topmost surfaces.
- The fake theft recording shows only the bundled generic prop; an API/dependency trace confirms Gary never enumerates or modifies real desktop content.

## M4 — Gary Event

**Depends on:** M3's complete signal priority, environment gates, overlays, monitor geometry, audio, and cleanup.

**Outcome:** Scary Mode can produce the exact rare, persistent, monitor-local Gary Event, and `gary.exe --rehearse-event` can prove the same production scene immediately without changing history.

**Build:**

- Add the eight-eligible-awake-hour gate, one 1/3600 roll per eligible minute, persist-at-blink consumption, conservative 72-hour wall-clock cooldown, and failure policy resolved in #6 and #10.
- Play one 300 ms dark blink, exactly three seconds of silent Gary absence, then the canonical face and one 900 ms sound hit, followed by immediate destruction and neutral Awake recovery.
- Use the standalone production assets, cursor-monitor bounds, aspect-preserving crop, bounded jitter, no focus/input capture, and exact stop/Esc/environment interruption behavior.

**Closure evidence:**

- A04 passes with fake time/entropy, restart and corruption cases, write-before-visibility ordering, exact scene timing, missing/muted audio, interruption, consumed failure, and history-free rehearsal.
- F14 has linked evidence for both normal eligibility policy and the production rehearsal Primary Scene, cleanup, and Safe Fallback.
- A supported Windows 11 run of the H06 procedure records normal, muted, and unavailable-audio rehearsal, monitor scope, crop/jitter, pass-through, focus, higher-surface yielding, and immediate restoration. M7 repeats H06 on both promised Windows generations against final bytes.

## M5 — Complete lifecycle and failure control

**Depends on:** M4's cross-session Event state and the complete session cleanup path.

**Outcome:** Portable Run, Gary Startup, Garynap, termination, crashes, upgrades, disablement, and Gary Removal behave as one comprehensible lifecycle without persistence repair or same-sign-in resurrection.

**Build:**

- Enforce one resident process per user without resetting the existing session. Implement the exact `--enable-startup`, `--disable-startup`, `--remove`, and `--rehearse-event` one-shot modes.
- Own only the quoted `HKCU` Run value and `%LOCALAPPDATA%\ScaryGary` state/log. Keep missing/corrupt/incompatible state conservative and writes atomic.
- Make removal idempotent: disable Startup first, request graceful stop, clear Gary-owned state, report partial failure safely, and leave the portable executable user-owned.
- Add no watchdog, restart registration, force-kill, self-delete, repair loop, updater, service, helper, or concealed component.

**Closure evidence:**

- A07 passes for single instance, exact Startup authority, Starting/Awake/Event Garynap, non-extension and monotonic return, Task Manager stop, sign-in return, disablement, two removals, stale registration, missing executable, state failures, upgrade paths, repeated presentation failure, crash, and absence of restart machinery.
- E13-E20 have linked results from disposable per-user Windows tests; registry and filesystem snapshots show only Gary-owned state changes and preserve the required Event history.
- A supported Windows 11 H05 rehearsal records the lifecycle and failure flow, including a forced crash and retryable removal failure. M7 repeats the required portions on both promised Windows generations against final bytes.

## M6 — Public distribution candidate

**Depends on:** M5's final command, state, and removal behavior.

**Outcome:** One release-candidate `gary.exe` can be inspected, reproduced, signed, identified, downloaded safely, started intentionally, and removed exactly as disclosed.

**Build:**

- Complete the README Gary Disclosure, spoiler boundary, pinned source-build instructions, exact tested-support wording, asset/dependency notices, and version-pinned PowerShell and `curl.exe` download-and-hash examples.
- Pin the release SDK and package lock; build in CI, retain provenance, Authenticode-sign and RFC 3161 timestamp the final candidate, verify it, then generate `SHA256SUMS.txt` from those bytes.
- Prepare a draft immutable GitHub Release containing only `gary.exe` and `SHA256SUMS.txt` in addition to GitHub's generated source archives. Do not publish, tag, or call it v0.1 yet.

**Closure evidence:**

- Locked restore, full automated tests, self-contained single-file publish, signature/timestamp verification, checksum verification, source-build instructions, license/provenance audit, and dependency/API safety audit pass on the candidate commit.
- A08 and A09 pass in full. Clean-machine smokes cover E01, E02, and E21, including no system runtime, no elevation/network prompt, consumer Windows 10 caveat, and safe rejection of unsupported targets.
- README and draft-release review proves the disclosure precedes download, exact commands match M5, downloads never execute or enable Startup, and no instruction weakens Windows security.
- The candidate commit, SDK, CI run, signer identity, executable SHA-256, and exact Windows builds are recorded for M7.

## M7 — Rough-complete v0.1 release

**Depends on:** One unchanged M6 release-candidate checksum. Any fix returns to the affected milestone gate and creates a new candidate checksum.

**Outcome:** Every promised behavior and environment row is proven on release bytes, the owner accepts the evidence, and the same reviewed artifact becomes the immutable public v0.1 release.

**Closure evidence:**

1. Run A01-A09 in full on the release commit. A retry or partial milestone result cannot replace a clean final run.
2. Run H01-H06 against the same signed `gary.exe` checksum, including clean supported Windows 11, mixed-display movement, high-DPI/shell changes, consumer Windows 10 22H2, lifecycle/failure, and Gary Event production review.
3. Link a result for every F00-F14 and E01-E21 row. No required row is failed, skipped, waived, or represented only by a fallback demonstration.
4. Itemize remaining debt and reject anything outside the acceptance contract's allowed-polish column. Rerun the affected focused gate and complete automated suite after every fix.
5. Confirm final signature/timestamp, SHA-256, source commit, exact Windows builds, .NET support caveat, disclosure, Startup/removal instructions, and asset/dependency provenance.
6. Obtain explicit owner acceptance of the evidence, create the v0.1 tag from that commit, publish the prepared immutable release, download its assets, and re-verify signature and checksum from the public release.

Nothing in the original concept remains after M7: F00-F14 cover safe startup/loiter, all thirteen routine action families, and the Gary Event; E01-E21 cover platform, environment, lifecycle, failure, and unsupported-target behavior; A01-A09 and H01-H06 provide the required automated and hands-on proof.
